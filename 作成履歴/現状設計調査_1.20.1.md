# lolMOD 現状設計調査（Minecraft Forge 1.20.1）

## 1. 対象と前提
- 対象リポジトリ: `MinecraftMOD_test/lolmod`
- 想定実行環境: **Minecraft 1.20.1 + Forge 47.3.0 + Java 17**
- 目的: 1.20.1 移行後の現在コードの設計状態と未実装範囲を明確化する

## 2. 全体アーキテクチャ
主要な構成は以下の4層（1.19.4から変わらず）。

1. 初期化層
- `LolMod.java`
- Config登録、イベント登録、ネットワーク初期化、modディレクトリ作成を担当

2. ドメイン層（ゲームロジック）
- レベル: `level/LevelManager.java`
- マナ: `mana/ManaManager.java`
- ステータス: `status/PlayerStatus.java`

3. 入出力層
- 永続化: `level/PlayerDataManager.java`（JSON保存）
- 通信: `level/PacketHandler.java`, `SyncLevelDataPacket.java`, `SyncManaDataPacket.java`
- 設定: `level/LolModConfig.java`

4. 表示層（HUD）
- `level/Hud.java`（Level/Manaバー）
- `status/StatusHud.java`（各種ステータス表示）

## 4. 実装済み機能（1.20.1時点）

### 4.1 レベルシステム
- スケルトン撃破時にXP付与（`EntityEvents.onEntityDeath`）
- `baseXP * rate^(level-1)` で必要XPを計算
- レベルアップ時にマナ最大値更新 + 全回復
- レベル/XPをJSONに永続化
- `Map<UUID, LevelManager>` によるマルチプレイ対応

### 4.2 マナシステム
- `ModCapabilities` でプレイヤーに `ManaManager` をアタッチ
- 最大マナはレベル依存（`100 + level*10`）
- `player.getPersistentData()` へ保存
- サーバー → クライアント同期（`SyncManaDataPacket`）

### 4.3 ステータスシステム
- `Map<UUID, PlayerStatus>` + `@EventBusSubscriber` によるプレイヤー単位管理
- レベル依存で移動速度/最大体力/防御率/AD/AP等を計算
- 属性値を `AttributeModifier` で適用
- 被ダメージ時に軽減率を計算してダメージ補正
- HUDにAD/AP/防御/CD/移動速度などを表示

## 6. 残存課題

### 6.1 永続化方式の分散（未解決）
- レベルはJSONファイル、マナは `persistentData` で保存方式が異なる
- 将来的に統一Capability設計へまとめることを推奨

### 6.2 ステータス更新タイミング
- `PlayerStatus.updateStats()` はログイン/リスポーン時に呼ばれるが、レベルアップ時の自動呼び出しを確認・整備する必要あり

### 6.3 AttributeModifier のUUID指定
- 現在はUUIDハードコードで動作するが、1.21以降では `ResourceLocation` ベースへの変更が必要になる予定
