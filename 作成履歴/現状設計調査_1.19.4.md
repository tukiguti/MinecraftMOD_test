# lolMOD 現状設計調査（Minecraft Forge 1.19.4）

## 1. 対象と前提
- 対象リポジトリ: `MinecraftMOD_test/lolmod`
- 想定実行環境: **Minecraft 1.19.4 + Forge 45.3.0 + Java 17**
- 目的: `作成履歴` の計画内容に対して、現在コードで実装済みの設計と未実装範囲を明確化する

## 2. 全体アーキテクチャ
主要な構成は以下の4層。

1. 初期化層
- `LolMod.java`
- Config登録、イベント登録、ネットワーク初期化、modディレクトリ作成を担当

2. ドメイン層（ゲームロジック）
- レベル: `level/LevelManager.java`
- マナ: `mana/ManaManager.java`
- ステータス: `status/PlayerStatus.java`

3. 入出力層
- 永続化: `level/PlayerDataManager.java`（JSON保存）
- 通信: `level/PacketHandler.java`, `SyncLevelDataPacket.java`, `SyncManaDataPacket.java`
- 設定: `level/LolModConfig.java`

4. 表示層（HUD）
- `level/Hud.java`（Level/Manaバー）
- `status/StatusHud.java`（各種ステータス表示）

## 3. 実装済み機能（設計ベース）
### 3.1 レベルシステム
- スケルトン撃破時にXP付与（`EntityEvents.onEntityDeath`）
- `baseXP * rate^(level-1)` で必要XPを計算
- レベルアップ時にマナ最大値更新 + 全回復
- レベル/XPをJSONに永続化

データフロー:
1. `LivingDeathEvent` 発火
2. `LevelManager.addXP()`
3. `PlayerDataManager.savePlayerData()`
4. `SyncLevelDataPacket` をクライアントへ送信
5. HUD再描画で反映

### 3.2 マナシステム
- `ModCapabilities` でプレイヤーに `ManaManager` をアタッチ
- 最大マナはレベル依存（`100 + level*10`）
- 現在マナは `useMana/addMana/setCurrentMana` で更新
- `player.getPersistentData()` へ保存

### 3.3 ステータスシステム
- レベル依存で移動速度/最大体力/防御率/AD/AP等を計算
- 属性値を `AttributeModifier` で適用
- 被ダメージ時に軽減率を計算してダメージ補正
- HUDにAD/AP/防御/CD/移動速度などを表示

## 4. 作成履歴との対応
`タスク管理.txt` の最優先（レベル・マナ・ステータス）は、**基本機能+HUDまで実装済み**。

未着手または限定的:
- チャンピオン選択UI
- チャンピオンスキル（Q/W/E/R）
- サモスペ
- ミニオン固有エンティティ
- アイテムシステム
- ルーン

## 5. 現状設計の重要課題（要修正）
### 5.1 単一インスタンス設計の問題
- `LevelManager` が `static LevelManager instance` のため、複数プレイヤーやサーバー環境で競合しうる。
- 本来は `Map<UUID, LevelManager>` か Capability化が必要。

### 5.2 起動時NPEリスク
- `LolMod.commonSetup()` で `PlayerDataManager.loadPlayerData(null)` を呼んでおり、null参照の可能性が高い。

### 5.3 イベント登録の重複リスク
- `StatusHud` の毎フレーム描画内で `new PlayerStatus(player)`。
- `PlayerStatus` コンストラクタで `MinecraftForge.EVENT_BUS.register(this)` しているため、登録が増殖する設計。

### 5.4 マナ同期の整合性
- `SyncManaDataPacket` 受信側で `msg.maxMana` を直接反映せず、`updateMaxMana()` を呼ぶ実装。
- サーバー値とクライアント表示がズレる余地がある。

### 5.5 永続化方式の分散
- レベルはJSONファイル、マナはpersistentDataで保存しており、保存戦略が統一されていない。

## 6. 1.19.4向け設計としての次ステップ
1. `LevelManager` と `PlayerStatus` をプレイヤー単位管理へ修正（Capability推奨）
2. `loadPlayerData(null)` を廃止し、ログインイベントで初期化
3. ステータス更新を「ログイン/レベルアップ/装備変更時」に限定し、描画と分離
4. 同期パケットはサーバー権威で値を直接適用する方針に統一
5. その後にチャンピオン選択UI -> Q/W/E/R実装へ拡張

この時点で、1.19.4向け土台（レベル・マナ・ステータス）は成立しているが、マルチプレイ前提では設計修正が先に必要。
